# 설계 배경 · 철학 · 로드맵 (DESIGN)

이 문서는 `paju-quant-weekly` 프로젝트가 **왜 이렇게 설계되었는지**를 기록한다.
코드(`index.html`, `collect_data.py`, `collect_fundamentals.py`)의 의사결정 근거이며,
향후 기능 추가·수정 시 이 문서의 원칙을 먼저 검토한다.

> ⚠️ 교육·학습용 도구다. 투자 권유가 아니며, 모든 투자 판단과 책임은 본인에게 있다.

---

## 1. 배경 — 김민겸(MinKyeom Kim) 우승 전략

- **인물**: UNIST(울산과학기술원) 산업공학·경영학 복수전공 학생.
- **성과**: 2025년 10월 12일 싱가포르, 월드퀀트(WorldQuant) 주최 **제5회 국제 퀀트
  챔피언십(IQC)** 세계 1위. 142개국·1만1천여 개 대학·8만여 명 참가, 결선 11명 중 완승.
  총상금 약 2만3천 달러. 2026년 7월 월드퀀트 본사 인턴십 자격 획득.
- **평가 기준**: 정량 점수(수익률·리스크관리) 50% + 전략 논리·발표 50%.

### 우승 알고리즘의 핵심 4가지

1. **롱숏 에쿼티(Long-Short Equity)** — 상승 예측 종목 롱, 하락 예측 종목 숏.
2. **"적지만 강한" 포트폴리오** — 타 팀 알파(알고리즘) 200~300개 vs. 그는 **32개 정예**.
   각 알파를 정교하게 다듬어 소수로 승부.
3. **거시경제 국면 반영** — 시장을 저금리·고금리·확장기·침체기 **4국면**으로 나누고
   국면별 전략을 다르게 설계.
4. **투자심리 데이터 결합** — 종가·재무제표 등 정량 데이터에 더해 **뉴스 모멘텀**,
   특히 옵션의 **내재변동성(Implied Volatility)** 알파가 가장 효과적이었음(공포/안도
   시점 차이 분석).

### 설계 철학 (프로젝트의 최상위 원칙)

> "너무 복잡한 모델은 과거 데이터에 **과적합(overfitting)**되기 쉽다.
> 단순하지만 **금융적으로 설명 가능한 전략**이 실전에서도 강하다."

AI는 데이터 분석 조교로 활용하되, 어떤 알고리즘을 만들고 어떤 투자 철학을 세울지는
**인간의 판단 영역**으로 남긴다.

## 2. 핵심 개념의 수학적 표현

### ① 알파의 기본 형태
각 종목에 얼마의 비중을 줄지 계산하는 함수. 양수=롱, 음수=숏.
```
alpha_i = f(종목 i의 데이터)
```
고전적 평균회귀 예: `alpha_i = -(오늘 수익률)` — 어제 급등=숏, 급락=롱.

### ② 롱숏 중립화 (시장 위험 제거)
```
alpha_i ← alpha_i - mean(alpha)     # 중립화 (롱 금액 = 숏 금액)
weight_i = alpha_i / Σ|alpha_i|     # 정규화 (비중 합 = 1)
```
시장 전체 등락이 상쇄되고, 순수하게 "종목 간 상대 우열"에만 베팅.

### ③ 거시 국면(Regime) 분류 — 2개 지표로 단순화
- **금리 축**: 기준금리 > 최근 3년 중앙값 → 고금리, else 저금리
- **경기 축**: 코스피(200) 200일 이동평균 기울기 > 0 → 확장기, else 침체기

### ④ 알파 결합 (단위 문제 → rank 변환 필수)
```
최종 alpha_i = w1·alpha1_i + w2·alpha2_i + ... + wn·alphan_i
```
수익률(%)·PER(배수) 등 단위가 다른 지표를 그냥 더하면 큰 숫자가 지배하므로,
각 알파를 **순위(rank)로 변환한 뒤** 결합한다.

### ⑤ 평가 지표: 샤프 비율
```
Sharpe = (연평균 수익률 - 무위험 수익률) / 연 변동성
```
1.0 이상 준수, 2.0 이상 매우 우수.

## 3. 축소판 설계 — "3-알파 미니 포트폴리오"

32개는 무리이므로 성격이 다른 3개 알파로 시작한다. 데이터는 종가·거래량·PBR만 필요.

| 알파 | 수식 | 논리 |
|---|---|---|
| **α1 단기 평균회귀** | `-rank(최근 5일 수익률)` | 급등 숏·급락 롱 ("공포에 사서 환호에 판다") |
| **α2 중기 모멘텀** | `rank(최근 60일 수익률, 최근 5일 제외)` | 추세 추종. α1과 반대 성격이라 상호 보완 |
| **α3 밸류** | `-rank(PBR)` | 저PBR 롱. 재무 기반이라 위 둘과 상관 낮음 |
| **α4 추세 전환** | `rank(20일 수익률 − 직전 20일 수익률)` | 모멘텀 가속(2차 미분). 하락세가 꺾여 위로 트는 종목 롱. 침체기 가중 |

α4는 2026-07-08 실데이터 검증(`research/validate_alpha4.py`)을 통과해 추가:
기존 알파와 최대 |ρ|=0.32(독립), IS/OOS 모두 개선, 침체기 주간수익 +43→+86bp.
저점회복형(V3)은 α2와 ρ=0.74로 중복 판정되어 탈락 — "적지만 강한" 원칙 적용 사례.

### 국면 스위칭 (알파 가중치, α4 통합 후)
```
확장기: alpha ≈ 0.25·α1 + 0.45·α2 + 0.15·α3 + 0.15·α4
침체기: alpha ≈ 0.35·α1 + 0.10·α2 + 0.30·α3 + 0.25·α4
```
침체기엔 모멘텀이 잘 깨지므로 비중을 줄이고, 평균회귀·밸류·추세전환(α4)을
키운다. α4는 "바닥 탈출 종목 포착"이 목적이라 침체기에 가장 크게 가중.
(코드 `index.html` `detectRegime()`의 `W`는 4국면으로 세분화:
LO_EXP/HI_EXP/LO_REC/HI_REC.)

### 리스크 규칙
- 종목당 최대 비중 상한 (설계 논의 5%, 현재 프로토타입 코드 `CAP=0.15`)
- 유니버스는 유동성 좋은 대형주로 한정 (코스피200)
- 리밸런싱 주 1회 (매일 하면 수수료가 수익을 잠식)

### 검증 순서 (과적합 방지 — 김민겸이 가장 강조)
1. 과거 3~5년 백테스트 → 샤프·MDD 확인
2. 학습에 안 쓴 **최근 1년 out-of-sample** 재검증
3. 실제 돈 없이 **모의투자 3개월** 운영

## 4. 개발 원칙 (모든 향후 작업에 적용)

1. **단순성 우선 / 과적합 경계** — 알파·파라미터를 늘리자는 요구가 와도 "금융적
   설명 가능성"과 out-of-sample 검증을 먼저 따진다. 복잡도 추가는 정당화가 필요하다.
2. **롱온리 유지** — 한국 개인투자자는 공매도 접근이 제한적. 숏 신호는 "매수 제외"로
   해석하고, 상위 N종목 매수 방식으로 운용한다.
3. **유니버스 제한 고수** — 전 종목(약 2,600개) 스캔 ❌. 소형주는 신호가 노이즈투성이가
   되고 슬리피지·데이터 품질 문제가 크다. 검증된 대형주 200개 내 상대 비교가 본질.
4. **자동주문 금지** — 대시보드의 역할은 "이번 주 목표 비중표 제안"까지. 최종 매매
   판단·책임은 사용자. 자동 매매 연동은 넣지 않는다.
5. **데이터 로더 분리** — 실데이터/모의데이터 전환은 `loadData()` / `loadMockData()`
   한 지점에서만 일어나도록 유지한다. 소스가 바뀌어도 알파·국면·백테스트 로직은 불변.
6. **면책 유지** — 모든 산출물에 "교육·학습용, 투자권유 아님" 문구를 유지한다.
7. **보안** — API 키(DART·ECOS·KRX)는 절대 코드에 하드코딩하지 않는다.
   `config.json`(gitignore) 또는 환경변수로만 로드한다.

## 5. 데이터 소스 전략

무료 공공 API 조합으로 필요한 데이터를 100% 커버 가능. 대부분 CORS 제한으로 브라우저
직접 호출은 불가 → 파이썬 수집 스크립트가 JSON을 생성하고 대시보드가 읽는 구조.

| 갱신 주기 | 데이터 | 용도 | 출처 |
|---|---|---|---|
| 주간 | 일별 종가(최근 90일+) | α1(5일), α2(60일) | pykrx / KRX |
| 주간 | 거래량·시가총액 | 유동성 필터, 비중 상한 | pykrx / KRX |
| 주간 | 코스피200 지수 | 200일선 기울기(국면), 벤치마크 | pykrx / KRX |
| 월간 | 한국은행 기준금리 | 3년 중앙값 대비 고/저 판정 | ECOS |
| 월간 | 국고채 3년·10년(선택) | 장단기 스프레드(침체 선행) | ECOS |
| 분기 | PBR 또는 자본총계 | α3 | pykrx 또는 DART |

**우선순위**: 주가·PBR은 **pykrx**로 즉시 시작(키 불필요) → 안정성 필요 시 KRX 공식
API로 교체 → **DART**는 자본총계로 PBR 직접 계산(`시가총액 ÷ 자본총계`) 및 향후 공시
이벤트 알파용 → **ECOS**는 기준금리 히스토리 자동화용(없으면 `base_rate_manual` 수동값).

## 6. 대시보드 5-패널 구조 (설계 의도)

1. **국면 배너** — 현재 4국면 중 어디인지 + 판정 근거(금리 vs 3년 중앙값, 200일선
   기울기)를 숫자로 노출. "왜 이번 주 모멘텀 비중이 낮은가"를 한눈에 이해시키는 게 목적.
2. **알파 패널** — 3개 알파 각각의 최근 성과 미니차트. 어떤 알파가 지금 작동하는지 가시화.
3. **포트폴리오 패널(핵심)** — 이번 주 목표 비중표. "지난주 대비 변경분만 보기"가 실사용 최고 유용.
4. **성과 패널** — 백테스트 누적수익 곡선(vs 벤치마크), 샤프·MDD·승률. 거래비용 반영.
5. **리밸런싱 이력 패널** — "확정" 버튼으로 그 시점 국면·상위종목을 스냅샷 저장
   (localStorage). 나중에 "그때 왜 그렇게 했는지" 복기 → 초보자 학습의 최대 가치.

## 7. 단계별 로드맵

- **1단계 (완료)** — 내장 모의 데이터로 대시보드 골격 + 백테스트. 알고리즘 검증.
  - 교훈: 순수 랜덤 데이터에선 전략이 벤치마크에 짐. "알파는 패턴이 존재할 때만
    작동한다"를 확인 → 모의 데이터에 약한 평균회귀·모멘텀·밸류 효과를 심어

  - 유의: 최신 pykrx는 `data.krx.co.kr` 무료 회원가입 + 환경변수(`KRX_ID`/`KRX_PW`) 필요.

  어떤 기기도 파이썬 실행 불필요, 갤럭시탭 등에서 URL 열람만.
- **4단계 (완료, 2026-07-08)** — α4 추세 전환 알파 추가. 오프라인 검증 게이트
  (중복성→단독→IS/OOS→국면별) 통과 후 통합. `research/validate_alpha4.py` 참고.

  - ECOS 키 연동 → 기준금리 히스토리 자동화(온전한 4국면 판정). 코드 준비 완료,
    `ECOS_API_KEY` Secret 등록만 남음.

  - **IV 알파 / 뉴스 모멘텀 알파** 추가 — 김민겸 전략의 정수이므로 향후 최우선 확장 후보.

## 8. 반드시 알아둘 한계

1. **숏은 개인이 실행하기 어렵다** → 롱온리로 변형. 시장 전체 하락 위험은 남는다.
2. **예측이 아니라 확률적 우위** — 샤프 1.5는 "과거 평균적으로 유리했다"는 뜻이지
   다음 주 특정 종목 상승 보장이 아니다. 여러 종목·여러 주에 걸쳐 평균적으로 이기는 구조.
3. **백테스트가 좋아도 실전은 다를 수 있다** — 과적합·수수료·슬리피지·국면 변화.
   반드시 out-of-sample 검증 → 모의투자 → 소액 순서를 거친다.
